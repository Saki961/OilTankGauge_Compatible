# 原油舱容检尺 Android App

这是一个可直接用 Android Studio 打开的 Kotlin 工程，面向石油码头检船现场。

## 当前已实现

- 本地导入并原样保存 `.xlsx` 舱容表
- 不联网，所有文件和数据库均保存在手机 App 私有目录
- 遍历所有工作表，不依赖固定行列；表头可位于不同的行和列
- 识别船号、船舱、空高、容积
- 带纵倾矩阵时默认提取 `0.0m` 列
- 支持一张工作簿识别多艘船
- 同一船舱跨多个 Sheet 时按空高合并
- 船号完全匹配、标准化匹配和包含搜索
- 检尺空高默认使用毫米，可切换为米
- 使用相邻点线性插值，结果保留 3 位小数
- 输出 H1、H2、V1、V2、比例、公式、原始单元格等过程数据
- 本地船舶资料库、版本更新、船号修改、船舱映射修改
- App 内浏览原始工作表内容
- 调用 WPS / Excel 查看原始版式
- 内置本次提供的示例表，方便安装后测试

## 开发环境

兼容版固定使用：

- Android Gradle Plugin 8.2.2
- Gradle 8.2.1
- Kotlin 1.9.22
- Android API 34
- JDK 17

该组合可由 Android Studio Hedgehog（2023.1.1）及更新版本打开。

## 打开与运行

1. 解压工程。
2. 用 Android Studio 打开工程根目录 `OilTankGauge`。
3. 等待 Gradle Sync。
4. 连接 Android 8.0（API 26）及以上设备。
5. 运行 `app`。
6. 首页可先点击“导入内置示例表”测试。
7. 导入后进入“船舶资料库”，检查自动识别的船舱名称；必要时点击“修改船舱映射”。

## 数据处理规则

### 船号匹配

输入如 `新平江1014`。程序会：

- 全角字符转半角
- 移除空格和常见分隔符
- 英文字母忽略大小写
- 完全匹配优先
- 无完全匹配时进行包含搜索

### 空高单位

- 页面默认 `mm`
- 可切换到 `m`
- 数据库统一按整数毫米保存，避免浮点定位误差

### 纵倾

- 带纵倾表默认读取 `0.0m`
- 找不到 `0.0m` 时不会擅自选择其他纵倾列

### 容积计算

```text
V = V1 + (H-H1)/(H2-H1) × (V2-V1)
```

- 正好命中数据点时直接取表值
- 超出有效范围时禁止外推
- 最终结果四舍五入保留 3 位小数

## 当前边界

- 当前版本只读取 `.xlsx`，不读取旧版二进制 `.xls`。
- App 内表格浏览器以内容核对为主，不完整还原 Excel 的颜色、合并单元格和打印样式；使用 WPS/Excel 打开可查看原始版式。
- 自动解析采用通用启发式规则。新的船型第一次导入后，应检查船号、船舱映射、点数和空高范围。
- 示例中的个别单元格存在小数点丢失，解析器对明显的六位容积数按千分位修正并保留原始文本用于追溯。
- 在正式生产使用前，需要用实际船舶表样本做回归测试，并由现场人员核对计算结果。

## 1.1.0 原油综合计算升级

新增“原油综合计算与 XLSX 输出”：

- 最多 12 个船舱，空舱取消勾选后不参与温度平均。
- 逐舱输入检尺空高和中部温度，复用原有 0.0m 舱容插值。
- 输入商检量、管线量、水体积、OBQ、密度和 VCF。
- 密度可选 kg/m³ 或 t/m³，内部统一换算为 t/m³ 并执行 P20-0.0011 修正。
- 输出总检尺容积、平均油温、有/无钢膨标准体积、净表观质量和量差。
- 基于 `assets/report/原油计算模板.xlsx` 生成 A1:L26 格式报表，第 26 行改为两组量差记录。

测试阶段不处理旧数据库迁移；建议安装新包前清除 App 数据后重新导入。
